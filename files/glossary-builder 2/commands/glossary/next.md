---
description: Обработать следующий тикет из очереди
---

Обработай следующий тикет. Аргумент `{{args}}` — ключ конкретного тикета,
если он задан; иначе бери следующий из очереди.

**1.** Узнай, что обрабатывать:

```
node scripts/status.mjs
```

Очередь идёт строго по возрастанию `order` — то есть по спринтам и датам закрытия.
Не переставляй тикеты местами: порядок нужен, чтобы поздние решения перекрывали
ранние, а не спорили с ними.

**2.** Запусти `glossary-ticket-researcher` на этот тикет, **обязательно с
`run_in_background: false`**. Один агент за раз. Параллельный запуск создаёт гонку
за один и тот же файл карточки.

Передай агенту только ключ тикета. Всё остальное он возьмёт из `out/` сам.

**3.** Когда агент вернётся, отметь тикет:

```
node scripts/status.mjs --done PROJ-1234
```

Тикет, который агент не смог разобрать, отмечай `--skip` и убедись, что причина
записана в `_unresolved.md`.

**4.** Каждые 10 тикетов запускай `glossary-merger`, тоже последовательно. Не
после каждого тикета — он работает с общей картиной, и на одном тикете ему нечего
сводить.

**5.** Коротко отчитайся: какой тикет обработан, что попало в глоссарий, что
осталось непонятным. Не пересказывай карточку — она уже на диске.

Не запускай следующий тикет автоматически. Человек решает, продолжать ли.
