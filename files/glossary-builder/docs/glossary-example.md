# Пример глоссария: структура и формат

Домен в примерах условный (заявки), подставь свой. Названия глав, слайсов и тикетов вымышленные.

## Структура на диске

```
docs/glossary/
  index.md                        # корневой индекс, читается агентом ВСЕГДА
  chapters/
    orders.md                     # глава: обзор + список модулей
    profile.md
    reports.md
  modules/
    order-create-form.md          # карточка модуля
    order-status-timeline.md
    order-filters.md
  shared/
    api-client.md                 # карточка общей инфраструктуры
    date-format.md
  terms.md                        # термины без привязки к коду
  _unresolved.md                  # очередь на ручной разбор
```

Правило размера: `index.md` должен влезать в контекст всегда, поэтому не больше ~200 строк. Всё остальное подгружается по требованию.

## `modules/order-create-form.md` — карточка модуля

Основная единица глоссария. Показываю с комментариями, зачем каждое поле.

```markdown
---

title: Форма создания заявки
chapter: orders
status: active            # active | frozen | deprecated
aliases:                  # как это называют в тикетах и в коде
  - форма подачи
  - визард заявки
  - OrderWizard
  - CreateOrderForm
rootPath: src/features/order-create/
provenance: from-ticket   # from-ticket | from-code | unknown-legacy
confidence: high
lastVerified: 2026-08-30
sourceTickets: [PROJ-1204, PROJ-1288, PROJ-1401, PROJ-1590]
---

## Назначение

Многошаговая форма подачи новой заявки. Три шага: параметры, документы,
подтверждение. Черновик сохраняется на бэке после каждого шага.

## Бизнес-термины

|---|---|---|
| заявка | `Order` | в reports-модуле та же сущность зовётся `Request` — расхождение, см. terms.md |
| черновик | `OrderDraft` | |
| шаг подтверждения | `ConfirmStep` | в тикетах также «финальный экран» |

## Поведение

- Переход на следующий шаг блокируется, пока текущий шаг не валиден.
- Черновик сохраняется при переходе между шагами и при закрытии вкладки.
- При восстановлении черновика пользователь попадает на последний заполненный шаг.
- Загрузка документов — до 10 файлов, каждый до 20 МБ, форматы pdf/jpg/png.

## История решений

| PROJ-1288 | 44 | Валидация ИНН по контрольной сумме на клиенте | актуально |
| PROJ-1401 | 48 | Шагов стало 3 (объединены «документы» и «вложения»); черновик переехал на бэк | актуально |
```

## `shared/api-client.md` — карточка общей инфраструктуры

Формат другой: не «какую фичу реализует», а «что предоставляет и кто зависит».

```markdown
---
id: api-client
title: HTTP-клиент
kind: shared
category: hot             # из files-index.json: ticketCount = 34
status: active
rootPath: src/shared/api/client.ts
provenance: from-code
confidence: high
targetTickets: [PROJ-1010, PROJ-1156]
---

## Что предоставляет

Обёртка над `fetch`: подстановка токена, единый разбор ошибок бэка,
ретраи на 5xx, отмена по AbortSignal.

## Почему он такой

Файл меняется в среднем в каждом третьем тикете, но целью задачи был лишь дважды:

- **PROJ-1010** (спринт 39) — добавлены ретраи на 5xx, максимум 3 попытки,
  экспоненциальная задержка.
- **PROJ-1156** (спринт 45) — единый формат ошибки `ApiError` с полем `code`,
  вместо разбора ответа на каждом вызове.

В остальных 32 тикетах правки попутные: добавление эндпоинта, правка типа.

## Кто зависит

45 файлов. Модули: order-create-form, order-filters, profile-edit, reports-export
и ещё 6. Полный список — `git grep`, здесь не дублируется намеренно.

## На что обратить внимание при изменении

- Меняешь формат `ApiError` — ломается обработка ошибок во всех формах.
- Ретраи не отключаются точечно; если нужен запрос без ретраев, используй
  `client.raw()`.
```

## Что здесь важнее всего

1. **`provenance` и `confidence` в каждой карточке.** Агент должен видеть, где данные восстановлены по тикету, а где — предположение по коду.
2. **«История решений» вместо «требований».** AC тикета — это дельта, а не состояние. Список требований, собранный сложением сорока AC, будет внутренне противоречивым, и агент честно реализует отменённое год назад. Хронология с пометкой «отменено» этого не допускает.
3. **`aliases`.** Именно по ним агент найдёт модуль, когда в новом тикете напишут «поправить визард».
4. **Отдельный формат для shared.** Список из 45 зависимых файлов в карточке бесполезен — важны те два тикета, ради которых файл вообще менялся, и предупреждения о последствиях правки.
5. **`_unresolved.md` не должен быть пустым.** Если после прогона он пуст — это не успех, а признак того, что агенты подгоняли ответы вместо того, чтобы честно признавать неопределённость.
